# 🕯 暖归 · 宠物善终服务预约告别与骨灰寄存平台

围绕**同一只宠物**，让宠物主人、客服、客服主管、寄存主管、接送员、礼仪师、火化师、纪念品制作、财务和管理者在同一工单上协同，
全流程记录承诺时间、见证材料、费用变化与家属确认；本期强化**骨灰寄存到期续费、授权与柜位处置**：
到期前按主人偏好提醒，续费三项校验，转长期比较柜位并防止承诺已占用位置，逾期多轮联系、受保护、双审批、处置留痕与执行前撤回。

- 后端：NestJS 11 + TypeORM + MySQL/MariaDB（端口 4000）
- 前端：Next.js 14 (App Router) + React 18（端口 3000）
- 数据库：本地免安装 MariaDB 10.11，**无需 root / docker / apt**，脚本自动下载到 `.local/`；或使用 **Docker Compose 一键启动**

## 一、本地启动

### 方式 A：Docker Compose 一键启动（推荐，需本机装有 Docker）

```bash
docker compose up --build      # 启动 mariadb + backend(4000) + frontend(3000)
```

- 首次启动后端会等待数据库就绪、自动建表，并在**空库时写入种子数据**；已有数据则保留不清除。
- 重置演示数据：`SEED_RESET=1 docker compose up backend`（或改 `docker-compose.yml` 中 `SEED_RESET`）。
- 打开 http://127.0.0.1:3000 （前端构建期通过 `NEXT_PUBLIC_API=http://127.0.0.1:4000` 指向本机后端）。

### 方式 B：一键脚本（免 Docker）

```bash
bash scripts/setup.sh   # 首次：下载 MariaDB → 建库建表 → 装依赖 → 写入种子账号与资源
bash scripts/dev.sh     # 启动：MariaDB + 后端 4000 + 前端 3000
```

打开 http://127.0.0.1:3000

### 方式 C：手动分步

```bash
# 1. 数据库（当前用户运行，数据在 .local/mysqldata）
.local/mysqlctl.sh start      # 启动（首次自动初始化、建库 pet_aftercare、建号 petapp/petapp123）
.local/mysqlctl.sh status     # 查看状态
.local/mysqlctl.sh stop       # 停止

# 2. 后端
cd backend
npm install
npm run seed                  # 建表（synchronize）+ 写入种子数据
npm run dev                   # http://127.0.0.1:4000

# 3. 前端（新终端）
cd frontend
npm install
npm run dev                   # http://127.0.0.1:3000
```

数据库连接可用环境变量覆盖：`DB_HOST / DB_PORT / DB_USER / DB_PASS / DB_NAME`。
若要连接已有的 MySQL，把这几个变量指向你的实例后直接 `npm run seed` 即可。

> 重置演示数据：`cd backend && npm run seed`（清空并重建业务数据）

## 四、本期新增：骨灰寄存到期续费、授权与柜位处置

14. **主人续费偏好与联系人有效性**：登记主/备联系人、首选渠道（电话/短信/微信/邮件/信函）与到期偏好（续费/取回/转长期）、提前提醒天数；客服核查并标记联系人有效/失效（空号、停机、拒收）。
15. **按偏好发送到期提醒**：到期扫描对临期柜位按偏好生成「续费 / 取回 / 转长期」提醒并记录柜位剩余期限，同类型提醒不重复发送。
16. **续费三项校验（缺一不可）**：
    - ① **柜位是否仍可续用**：受保护、被迁移指令预占、存在未完成处置指令时拒绝续费；
    - ② **年费价格是否变更**：比对上次寄存费用折算年费与当前年费，变更时必须家属确认知晓后才能续费；
    - ③ **是否存在未结服务费用**：有未确认费用变更或欠费时拦截，需先结清。
17. **转长期寄存（防止承诺被占柜位）**：客服比较当前可用长期柜位、等级/年费/10 年九折价与迁移时间，提出方案等待家属确认；方案确认前不预占，**家属确认时再次校验目标柜位仍空闲**，随即生成迁移指令并把目标柜位标记为「迁移预占（reserved）」，他人无法再承诺或迁入。
18. **逾期多轮联系与受保护状态**：客服对逾期柜位立案，逐轮登记渠道、结果、说明与证明材料（通话录音、短信截图、挂号信底单、上门照片）；完成规定轮次（默认 3 轮）仍无有效回应后，柜位进入**受保护待处置（protected）**，系统禁止释放、禁止再次分配、禁止直接续费。
19. **双审批与合规处置指令**：受保护案件先由**客服主管**审批下一步；再由**寄存主管**复核联系轮次、证明材料与授权文件，复核通过才可生成「迁移 / 继续保管 / 取回 / 其他合规处置」指令。
20. **处置执行留痕与家属回访**：执行时永久保留**原柜位**、记录交接人员（双方签字）、执行时间、交接证明；迁移会释放原柜位、占用新柜位并延长到期；执行后自动生成家属后续回访任务并记录回访结果。
21. **执行前撤回与状态恢复**：主人在处置执行前恢复联系，可撤回全部未完成指令——释放预占目标柜位、作废/冲红处置阶段账单、原柜位恢复占用/到期状态；家属随后可正常续费（处置案件闭环）。
22. **授权文件管理**：主人/客服上传身份证明、授权委托书、家属确认书、亲属关系证明等；寄存主管逐项「采信 / 不采信」，留痕于时间线。

业务主状态机：
`submitted → cs_confirmed → scheduled → picked_up → in_storage → farewell → cremating → fulfilled → completed`
（异常可 `cancelled`；费用未确认 / 纪念品未完成 / 未结清 / 骨灰未签收会阻止完结）

寄存处置状态机：
`（偏好提醒）→ 逾期立案 contacting →（多轮联系无回应）柜位 protected / awaiting_supervisor
→ awaiting_storage_review → ordered（指令 pending，目标柜位 reserved）→ executed（执行留痕+家属回访）`
任一步执行前家属恢复联系均可 `withdrawn`（撤回指令、恢复账单与柜位）；家属自行续费/取回则 `closed_resolved`。

## 五、验证方式（已实际执行）

### 自动化端到端脚本

```bash
cd backend
npm run seed     # 重置数据
npm run demo     # 需要后端已在 4000 运行
```

`scripts/demo-flow.ts` 通过真实 HTTP API 走通全部场景：

主人下单（全选项+医院转介）→ 客服方案 → 家属确认 → 调度 → 交通延误 → 接运复称自动补差 → 家属确认补差 →
改期 → 视频见证 → 告别 → 火化 → 纪念品失败→关怀→重做→完成 → 骨灰盒破损→补发→签收 → 收款 → 完结 →
第二只宠物跨店入柜 → 柜位扫描；随后：

- **场景 A（团团，逾期）**：补齐第 3 轮挂号信联系（留证）→ 柜位自动进入 `protected` → 客服主管批准 → 寄存主管复核
  （迁移未指定目标柜位被拦截）→ 生成「继续保管」指令 → **执行前家属恢复联系，撤回指令、柜位恢复 expired** →
  家属完成续费三项校验 → 续费成功柜位恢复占用；
- **场景 B（念念，临期+年费变更）**：续费校验检出年费 600→680；未确认知晓时续费被拦截；
  客服比较长期柜位提出方案 → 家属确认 → 目标柜位 `reserved`；再次向该柜位提方案被拦截（不承诺已占位置）；
  执行迁移并记录原柜位/交接人员/时间/证明 → 登记家属后续回访结果。

### 本次开发实际验证结论（2026-09-30）

- `npx tsc --noEmit`：后端类型检查通过（含 `docker-bootstrap.ts`）。
- `next build`：前端生产构建通过，**12 个路由全部生成**（新增 `/dispositions`）。
- `npm run seed`：2 门店、**17 账号**、24 柜位、2 个寄存处置演示场景写入成功；新增 5 张寄存处置表自动建表成功。
- `npm run demo`：全部业务流程与两个寄存处置场景跑通，输出「演示完成 ✅」，关键断言包括：
  续费金额精确（年费 680 元，无舍入误差）、受保护状态正确、双审批顺序正确、迁移后到期延至 2036 年、回访结果已留存。
- 额外合规拦截（curl 实测，均返回预期状态码）：
  - 跨店客服主管/寄存主管访问他店案件 → `403 跨门店数据不可访问`；主人访问他人案件 → `403`；
  - 联系中提前主管审批/寄存复核 → `400 当前状态无需…审批/复核`；
  - 受保护柜位走旧续费接口 → `400 柜位已受保护待处置…`；受保护柜位被再次分配 → `400 柜位非空闲`；
  - 客服（非主管）调用主管审批 → `403 当前角色无权操作`；
  - 存在未确认费用变更+欠费 80 元时 `renew-check` 返回 `can_renew:false` 并列明两条原因，直接续费被 `400` 拦截。
- 生产模式 `next start` 下 `/login`、`/dispositions`、`/lockers`、`/overview` 均返回 200。
- 管理者总览新增字段实测：`protected_lockers=1`、`reserved_lockers` 等正常返回。
