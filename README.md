# 🕯 暖归 · 宠物善终服务预约告别与骨灰寄存平台

围绕**同一只宠物**，让宠物主人、客服、接送员、礼仪师、火化师、纪念品制作、财务和管理者在同一工单上协同，
全流程记录承诺时间、见证材料、费用变化与家属确认，敏感争议可追溯到具体交接节点。

- 后端：NestJS 11 + TypeORM + MySQL/MariaDB（端口 4000）
- 前端：Next.js 14 (App Router) + React 18（端口 3000）
- 数据库：本地免安装 MariaDB 10.11，**无需 root / docker / apt**，脚本自动下载到 `.local/`

---

## 一、本地启动

### 方式 A：一键脚本（推荐）

```bash
bash scripts/setup.sh   # 首次：下载 MariaDB → 建库建表 → 装依赖 → 写入种子账号与资源
bash scripts/dev.sh     # 启动：MariaDB + 后端 4000 + 前端 3000
```

打开 http://127.0.0.1:3000

### 方式 B：手动分步

```bash
# 1. 数据库（当前用户运行，数据在 .local/mysqldata）
.local/mysqlctl.sh start      # 启动（首次自动初始化、建库 pet_aftercare、建号 petapp/petapp123）
.local/mysqlctl.sh status     # 查看状态
.local/mysqlctl.sh stop       # 停止

# 2. 后端
cd backend
npm install
npm run seed                  # 建表（synchronize）+ 写入种子数据
npm run dev                   # http://127.0.0.1:4000

# 3. 前端（新终端）
cd frontend
npm install
npm run dev                   # http://127.0.0.1:3000
```

数据库连接可用环境变量覆盖：`DB_HOST / DB_PORT / DB_USER / DB_PASS / DB_NAME`。
若要连接已有的 MySQL，把这几个变量指向你的实例后直接 `npm run seed` 即可。

> 重置演示数据：`cd backend && npm run seed`（清空并重建业务数据）

## 三、核心业务与页面

| 页面 | 角色 | 功能 |
|---|---|---|
| `/new` | 主人 | 提交猫/犬/兔/异宠善终预约：姓名、品种、体重、死亡时间、上门接送、纪念仪式、单独火化、骨灰盒、爪印毛发、照片视频、寄存期限、医院转介 |
| `/appointments` | 全部 | 工单列表（按状态筛选，员工只见本店，主人只见自己，管理者全部门店） |

| `/lockers` | 客服/管理者 | 寄存柜位年费管理、到期扫描、续费 |

业务状态机：
`submitted → cs_confirmed → scheduled → picked_up → in_storage → farewell → cremating → fulfilled → completed`
（异常可 `cancelled`；费用未确认 / 纪念品未完成 / 未结清 / 骨灰未签收会阻止完结）

## 四、已实现的需求场景

1. **客服确认方案**：系统按体重档位与服务选项生成建议报价（支持自定义总价），生成家属「服务方案确认」。
2. **调度排期**：一次排定接送员、冷藏暂存位、火化炉档期、告别室档期；火化炉/告别室同时段冲突会被拦截；重调度自动释放旧档期；按选项自动生成纪念品制作单。
3. **临时更改仪式时间**：家属发起改期申请 → 客服同意后告别室档期自动重排；驳回也留痕。
4. **体重与报价不符**：接送员接运复称后，按 20 元/kg 自动生成多退少补的费用变更，**必须家属确认**；存在未确认变更时火化环节被系统拦截。
5. **接送交通延误**：接送员上报分钟数与原因，承诺接运时间自动顺延，并在工单留言中通知家属。
6. **视频见证**：家属随时登记视频见证，火化完成时校验见证安排，证明中记录。
7. **纪念品制作失败**：开始 / 失败（原因）/ 重做（承诺 3 日交付）/ 完成；失败**立即生成客服关怀回访任务**，改变回访节奏。
8. **骨灰盒寄送破损**：登记快递单号 → 在途 → 家属反馈破损（照片+描述，触发关怀回访）→ 补发新单号 → 送达 → 家属确认完好签收。
9. **寄存到期未续费**：柜位 30 天内到期标记 `expiring` 并生成续费提醒；已过期标记 `expired` 并生成跟进；续费后自动关闭待办提醒。
10. **多门店 / 医院转介**：员工数据按门店隔离，管理者可看全部门店；主人下单可选转介医院。
11. **费用与财务**：基础报价与每次变更分行留痕，变更项需家属确认；财务登记收款/退款；完结前校验结清。
12. **见证材料与追溯**：每个交接节点（接运、入冷藏、告别、入炉、出炉、证明、寄送、入柜、回访…）都有操作人、角色、承诺时间、实际时间、备注、照片/视频 URL，时间线中异常（⚠）与已闭环（✓）一目了然。
13. **服务后留存**：交接照片、火化证明编号、寄存位置、寄送单号、费用明细、情感回访记录全部沉淀在工单详情。

## 五、验证方式（已实际执行）

### 自动化端到端脚本

```bash
cd backend
npm run seed     # 重置数据
npm run demo     # 需要后端已在 4000 运行
```

`scripts/demo-flow.ts` 通过真实 HTTP API 走通全部场景：

主人下单（全选项+医院转介）→ 客服方案 → 家属确认 → 调度 → **交通延误 40 分钟** → 接运复称
**4.2kg→5.0kg 自动补差 16 元** → 家属确认补差 → 家属改期并被批准 → **视频见证** →
冷藏 → 告别 → 火化（含未确认费用拦截校验）→ 火化证明 → 纪念品**失败→关怀回访→重做→完成** →
骨灰盒**寄送破损→补发→签收** → 财务收款 2026 元 → 完结（自动排 7 日安抚回访）→
第二只宠物（兔）跨店走通入柜寄存 → 柜位到期扫描。

### 本次开发实际验证结论

- `tsc --noEmit` 后端类型检查通过；`next build` 前端生产构建通过（11 个路由全部生成）。
- `npm run seed`：2 门店、13 账号、冷藏/火化炉/告别室/24 柜位写入成功。
- `npm run demo`：两单业务全流程跑通，末单 `completed`，时间线 32 个可追溯节点，自动生成 3 项待回访。
- 手动 SQL 将柜位到期时间改为昨天后调用 `POST /api/lockers/scan`：返回 `{"expired":1}`，
  柜位标记 `expired`，自动生成「到期未续费」回访；再调续费接口后柜位恢复 `occupied`、回访关闭。
- 越权校验：2 号店客服/司机访问 1 号店工单返回 `403 跨门店数据不可访问`；主人访问他人工单返回 403。

前端页面的操作通过后端 API 闭环验证；图形界面建议按 `demo-flow` 的顺序在浏览器点验一遍：
`owner1` 下单 → `cs1` 核定+调度 → `driver1` 延误/接运 → `owner1` 确认费用/改期 →
`rite1` 告别 → `fire1` 火化 → `art1` 纪念品失败重做 → `cs1` 寄送破损补发 → `fin1` 收款 → `cs1` 完结 → `manager1` 看总览。
