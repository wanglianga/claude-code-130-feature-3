# 🕯 暖归 · 宠物善终服务预约告别与骨灰寄存平台

围绕**同一只宠物**，让宠物主人、客服、客服主管、寄存主管、接送员、礼仪师、火化师、纪念品制作、财务和管理者在同一工单上协同，
全流程记录承诺时间、见证材料、费用变化与家属确认；本期重点实现**骨灰寄存到期续费、授权与柜位处置**的完整合规闭环：
到期按偏好提醒 → 续费三项校验 → 转长期寄存（柜位比较+家属确认）→ 逾期多轮联系 →
受保护待处置（不可释放/再分配）→ 客服主管审批 + 寄存主管复核授权与证据 → 处置指令留痕 →
执行前主人恢复联系可撤回并恢复账单与柜位。

- 后端：NestJS 11 + TypeORM + MySQL/MariaDB（端口 4000）
- 前端：Next.js 14 (App Router) + React 18（端口 3000）
- 数据库：MariaDB 10.11（Docker Compose 一键启动，或本地免安装脚本自动下载到 `.local/`）

## 一、本地启动

### 方式 A：Docker Compose 一键启动（推荐，需 Docker）

```bash
docker compose up --build
# 首次启动：后端容器等待数据库 → 自动建表 → 空库自动写入种子账号与资源
```

打开 http://127.0.0.1:3000 （后端 API：http://127.0.0.1:4000）

> 前端容器通过 `NEXT_PUBLIC_API` 接收浏览器访问后端的地址，默认 `http://127.0.0.1:4000`。
> 远程部署时用 `--build-arg NEXT_PUBLIC_API=http://<服务器IP>:4000` 重新构建前端。

### 方式 B：免安装脚本（无需 root / docker / apt）

```bash
bash scripts/setup.sh   # 首次：下载 MariaDB → 建库建表 → 装依赖 → 写入种子账号与资源
bash scripts/dev.sh     # 启动：MariaDB + 后端 4000 + 前端 3000
```

打开 http://127.0.0.1:3000

### 方式 C：手动分步（也可对接已有 MySQL）

```bash
# 1. 数据库（当前用户运行，数据在 .local/mysqldata）
.local/mysqlctl.sh start      # 启动（首次自动初始化、建库 pet_aftercare、建号 petapp/petapp123）
.local/mysqlctl.sh status
.local/mysqlctl.sh stop

# 2. 后端
cd backend
npm install
npm run seed                  # 建表（synchronize）+ 写入种子数据
npm run dev                   # http://127.0.0.1:4000

# 3. 前端（新终端）
cd frontend
npm install
npm run dev                   # http://127.0.0.1:3000
```

数据库连接可用环境变量覆盖：`DB_HOST / DB_PORT / DB_USER / DB_PASS / DB_NAME`。

> 重置演示数据：`cd backend && npm run seed`（清空并重建业务数据）

## 三、核心业务与页面

| 页面 | 角色 | 功能 |
|---|---|---|
| `/new` | 主人 | 提交善终预约：接送、仪式、单独火化、骨灰盒、纪念品、寄存期限、医院转介 |
| `/appointments` | 全部 | 工单列表（员工按门店隔离，主管/管理者可见全门店） |
| `/appointments/:id` | 全部 | 单只宠物工作台：方案/排期/费用/纪念品/寄送/相册/留言/时间线，以及**寄存续费·授权·柜位处置面板** |
| `/followups` | 客服/主管 | 情感回访中心（含临期提醒、受保护待处置、处置后家属回访） |
| `/lockers` | 客服/主管 | 柜位年费管理、到期扫描（按偏好生成提醒）、受保护柜位一览 |
| `/storage` | 客服/两级主管 | **寄存处置中心**：处置申请双级审批队列、指令执行/撤回/家属回访队列、统计 |
| `/overview` | 管理者/主管 | 单量、异常、应收已收、承诺超期、受保护柜位等预警 |

寄存业务状态机（柜位）：
`free → occupied → expiring（30 天内）→ expired（已到期）→ protected（受保护待处置/迁移预占）`
- 续费成功：回到 `occupied` 并延长到期；
- 转长期：源柜 `occupied` + 目标柜 `protected`（预占）→ 家属确认并执行 → 源柜释放、目标柜 `occupied`；
- 逾期处置：`expired → protected`（审批期间锁定）→ 双批准生成指令 → 执行；
  任一主管驳回或执行前撤回：解除保护、恢复 `expired` 继续跟进。

## 四、本期需求场景（寄存续费、授权与柜位处置）

14. **按主人偏好的到期提醒**：登记家属偏好（续费/到期取回/转长期寄存）与首选渠道（短信/电话/微信/邮件）、备用联系人；到期前 30 天与到期扫描自动按偏好生成提醒回访，记录**联系人有效性**（有效/空号停机/号码变更）。
15. **续费三项校验**：主人或客服办理续费时，系统校验 ①柜位仍可续用（受保护/迁移预占柜位禁止直接续费）②**年费价格是否变更**（入柜快照价 vs 现行价，变更须家属明示勾选确认，年差额实时展示）③**是否存在未结服务费用**（欠费先结清）；续费出账并更新年费快照与到期时间。寄存主管可调整柜位现行年费，下一轮续费自动提示差价。
16. **转长期寄存（柜位比较+家属确认）**：客服只能在系统列出的**当前空闲柜位**中比较（等级/年费），拟定迁移时间后生成方案；提交时二次锁定目标柜位（`protected` 预占），**已被占用/预占的位置无法承诺**；家属确认前不能执行，拒绝则自动撤回出账与预占；确认后执行迁移，原柜位释放、新柜位按年计费。
17. **逾期多轮联系留痕**：逐轮登记渠道（电话/短信/微信/邮件/上门/书面信函）、结果（接通/无人应答/空号/承诺续费/承诺取回/承诺转长期…）、联系时间与**证明材料**（通话截图、短信回执、挂号信回执、上门照片）；规定门槛为 **≥3 轮且覆盖 ≥2 种渠道**，空号自动联动联系人有效性。
18. **受保护待处置**：门槛满足后客服发起处置申请（迁移/继续保管/其他合规处置），柜位立即进入 `protected`：**不能直接释放、不能再次分配、不能直接续费**；迁移申请须选择空闲目标且理由合规。
19. **双级审批**：**客服主管**先审批下一步处理（驳回则解除保护回到过期跟进）；通过后**寄存主管复核授权文件与多轮联系证据**——迁移处置要求授权文件已核实、证据轮次/渠道达标、目标柜位仍空闲，任一不满足即驳回；复核通过才生成正式处置指令并预占目标。
20. **处置执行与留痕**：执行指令必须登记**交接人员、时间、交接材料**；系统永久保留**原柜位快照**（编号）、执行人、时间，并自动安排 7 日后**家属后续回访**（满意/理解/有顾虑/无法联系，结果回写时间线）。
21. **执行前撤回恢复**：处置执行前主人恢复联系，主人或客服可一键撤回未完成指令：冲销对应账单行（费用明细标记「已冲销」、应付恢复）、释放迁移预占目标柜位、原柜位解除保护恢复为已到期、申请标记已撤回，并重新生成到期跟进，供家属重新选择续费/取回/转长期。

其余既有场景（1-13）：客服报价确认、调度排期冲突拦截、改期、体重补差确认、交通延误顺延、
视频见证、纪念品失败关怀与重做、骨灰盒寄送破损补发、多门店隔离、费用财务、全程交接时间线等保持可用。

## 五、验证方式（已实际执行）

### 自动化端到端脚本

```bash
cd backend
npm run seed            # 重置数据（含 3 个寄存演示工单）
npm run demo            # 原有全流程（需后端已在 4000 运行）
npm run demo:storage    # 寄存续费/授权/柜位处置全链路断言脚本
```

`demo-flow.ts`：主人下单 → 方案 → 调度 → 延误 → 复称补差 → 改期 → 视频见证 → 告别 → 火化 →
纪念品失败重做 → 寄送破损补发 → 收款 → 完结 → 第二单入柜 → 柜位扫描。

`demo-storage.ts`（全部断言通过 ✓）：
- **续费校验**：欠费 200 元被拦截 → 财务结清 → 年费 600→660 未确认被拦截 → 勾选确认后续费成功（新到期约 370 天）→ 年费账单结清；
- **转长期**：比较 10 个空闲柜位 → 拟定方案后目标柜 `protected` 预占 → 再次承诺同一柜位被拦截（「不能承诺该位置」）、重复拟定被拦截 → 未确认禁止执行 → 家属确认后执行：新柜占用、原柜 B-01-02 释放、指令留存原柜位与交接人员、生成处置后回访、登记家属「满意」；
- **逾期处置**：三轮三渠道证明齐备 → 发起迁移申请后柜位 `protected`（续费/再分配均被 400/403 拦截）→ 客服主管批准 → 寄存主管因**授权未核实**驳回拦截 → 客服核实授权后复核通过生成指令 → 执行前**主人撤回**：原柜恢复 `expired`、预占目标释放回可比较列表、申请 `withdrawn`、迁移账单行 `voided` → 重新发起「继续保管」双审批 → 执行后柜位恢复占用、期限约 180 天；
- **越权**：普通客服调用主管审批接口返回 403。
- **家属取回（D）**：家属到店取回骨灰后柜位 A-01-01 立即释放、关联清空，时间线保留 `storage_retrieved` 交接节点；
  有在途迁移/处置指令或柜位处于保护态时取回会被拦截，须先撤回。
